# Journal Inspect

Native Swift macOS app and CLI sharing JournalCore. The reader opens Apple Journal directly through a read-only SQLite connection and indexes all entry metadata. No full database copy, text export or external decoder is used.

## Run

Run commands from the project root, one level above this documentation folder.

Open JournalInspect.xcodeproj, select JournalInspectApp, then choose **Sync Apple Journal**. Reading runs off the main thread, with aggregate progress and cancellation.

```sh
swift build
.build/debug/journal-inspect sync
# Optional source and metadata destination:
.build/debug/journal-inspect sync --source /path/to/moments.sqlite --output /path/to/private-directory
```

Default source: ~/Library/Group Containers/group.com.apple.moments/Library/moments.sqlite.

Default metadata index: ~/Library/Application Support/JournalInspect/journal-index.sqlite3.

The database stores UUIDs, dates, keyed fingerprints, deletion state and synchronization history only. It never stores bodies, titles or attachments. Keep the metadata index private and outside cloud-sync/shared folders. Permissions are 0700 for its directory and 0600 for its database.

## Personal memory

Open **Memory** to enable optional local background facts, add/edit facts, or build source-linked suggestions from all synced history. When memory is enabled, built source-supported memories provide bounded background automatically; confirmation is optional, and automatically extracted items remain labeled. Memory supports source navigation, dated corrections, forget/restore, resumable rebuilds, and delete-all. Disabling excludes it from prompts and stops automatic updates. After successful sync, enabled memory catches up.

Memory persists sensitive derived statements and source links separately in `~/Library/Application Support/JournalInspect/Memory/personal-memory.sqlite3` (0700 directory, 0600 file). The metadata index remains metadata-only. Answer generation caps memory at 900 actual model tokens and validates the full request including output reserve. See [PERSONAL_MEMORY.md](PERSONAL_MEMORY_2026-11-05.md) for controls, source invalidation, budgets and model-quality limits.

## Browse and open entries

The app lists 50 metadata records per page, newest entry date first (creation date fallback), with Previous/Next controls. Enable Date filter, select From/Through dates, then Apply. Both selected calendar days are included in the local timezone. Undated entries appear last and are excluded by date filters. Include deleted reveals indexed tombstones.

Select a row or enter an entry UUID and choose Open. The reader fetches its current body directly from Journal in a consistent read transaction, checks the current deletion flags and source identity, and decodes RTF using the native parser. Missing/deleted entries report an error even if an old index row still exists. Text stays in memory, clears on Close, paging, selection changes or synchronization, and is never written to the metadata index. The native text view supports selectable, scrollable larger entries. There is no body export command.

Last successful sync and the most recent attempt survive app restart. Counts describe committed changes; cancellation/failure preserves the previous index and success timestamp. Source-open failures are recorded too. Permission errors explain Full Disk Access for the actual app that is trying to read. No permission settings are changed automatically.

Core APIs: `JournalMetadataStore.browse(start:end:limit:offset:includeDeleted:)`, `syncStatus()`, and `JournalReader.openEntry(uuid:sourceID:)`. Store instances belong to the thread creating them; all UI database work runs off the main actor. API date filters are inclusive start / exclusive end. Offset pagination reflects the current index; a sync resets the UI to the first page.

## Design

See [design.md](design_2026-11-05.md) for the selected direct-read approach, alternatives, pros/cons, schema, cancellation, consistency and resource limits.

One source read transaction provides a stable entry/asset view. TEMP storage contains only numeric asset keys. SQLite may coordinate through WAL/SHM files; read-only does not mean every sidecar is untouched. Long reads may delay checkpoints and allow WAL growth. No source write command, schema change, journal-mode change or checkpoint is issued. No immutable flag or automatic copy fallback is used. Each sync still scans the full source.

The synchronous JournalReader.synchronize API must run off the main thread. JournalReader(maximumReadDuration:) defaults to a cooperative 60-second read budget; callers can explicitly choose a different budget. On cancellation/failure, incomplete index changes roll back. SQLite read coordination and macOS permissions can still prevent access. Grant Full Disk Access to the actual launching application if needed; no permissions are bypassed.

## Tests and code organization

Select JournalCoreTests or JournalInspectApp in Xcode and press Command-U, or run swift test. Tests use synthetic databases only. Suites cover synchronization, privacy, validation, fingerprints, cancellation and scale. JournalTestFixture owns synthetic schema/data generation. The same files are registered in project.yml and the generated Xcode project.

`Sources/JournalCore/Data` contains Journal reading, metadata indexing, and the on-demand retrieval adapter. `Sources/JournalCore/Prompt` contains retrieval contracts, context building, prompt augmentation, and assistant/tool interfaces. Both folders remain in the same JournalCore module.

JournalReader coordinates source access and streaming; JournalEntryCursor maps entry metadata; JournalAssetCursor walks assets; EntryFingerprint encodes fingerprints; JournalMetadataStore owns the local index; MetadataImport owns prepared writes for a scan. Database wraps SQLite and transactions.

Use one blank line between members and logical steps, keeping related declarations/statements together. The formatter preserves this spacing.

Earlier versions could save plaintext samples in JournalInspectData/journal.sqlite or a chosen output directory. Those files are left untouched. The vendored CLI is retained with its license but is not invoked or needed.

## Local embeddings

The separate JournalEmbeddings Swift target integrates a pinned llama.cpp XCFramework with Qwen3-Embedding-0.6B Q8_0. See [EMBEDDINGS.md](EMBEDDINGS_2026-11-05.md) for verified downloads, model storage, the synthetic `embedding-check` command and lifecycle APIs. ## Prompt augmentation

The app includes **Journal assistant — local Qwen**: prepare context by semantically searching all synced dates and selecting relevant excerpts within the prompt budget, review the evidence, then generate an answer locally using llama.cpp and a separate Qwen3 chat model (4B Instruct Q5_K_M preferred; 0.6B baseline retained for comparison). Journal bodies and answers stay in memory. See [GENERATION.md](GENERATION_2026-11-05.md) for model setup and usage, and [PROMPT_AUGMENTATION.md](PROMPT_AUGMENTATION_2026-11-05.md) for the retrieval interfaces and Apple Journal limitations.
